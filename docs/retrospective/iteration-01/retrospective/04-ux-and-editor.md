# UX и редактор: возможности должны ощущаться управляемыми

Снимок: `0.2.26`, commit `9d096834eadfacd9f04a551c5557b33194e7ca4b`.
Дата анализа: 2026-10-03. Наблюдения владельца продукта отделены от анализа кода:
в рамках этой ретроспективы пользовательский сеанс с измерением задержек не
проводился.

## Что показало использование

По оценке владельца, продукт получился широким и неудобным: новые возможности
появлялись раньше, чем предыдущие становились приятными в ежедневной работе.
Редактор был полезен, но его подход оказался недостаточно отзывчивым. Это
свидетельство о пользовательском опыте; оно не устанавливает, что виноваты
Monaco, React, сеть или Rust.

Первый полезный результат следующей итерации — уверенная работа с облачным
агентом через чат: быстро отправить уточнение, увидеть актуальный статус,
разрешить действие, прервать выполнение и вернуться после потери соединения.
Статус команды должен позволять отличить «интерфейс принял ввод», «Core принял
команду» и «агент выполнил действие». Ожидание модели не должно блокировать
интерфейс или маскировать отсутствие связи.

Текущий baseline уже содержит Managed runtime. Поэтому урок не состоит в том,
что интерактивная работа вовсе не реализована. Она стала отдельным поздним
направлением после множества других поверхностей; её наличие само по себе не
подтверждает удобство целого продукта. Историю и границы контрактов см. в
[архитектуре runtime](02-architecture-and-runtime.md) и
[релизах](../../../releases.md).

## Что удалось сохранить в Workbench

Первоначальная цель [workspace surface](../../../systems/areas/010-project-workspace-surface.md)
была разумной: человек должен видеть файлы, diff и терминал непосредственно,
а также иметь возможность исправить небольшую часть текста. Это уменьшает
зависимость от пересказа агента и создаёт адресуемые основания для review.

Реализация содержит полезные защиты и ограничения:

- [WorkspaceDrafts](../../../../apps/web/src/features/workspace-inspector/WorkspaceDrafts.tsx)
  хранит локальный черновик отдельно от полученного содержимого; новый remote
  content не перезаписывает dirty draft молча. Черновики разделены по
  placement и пути, а закрытие страницы с изменениями вызывает предупреждение.
- [WorkspaceWorkbench](../../../../apps/web/src/features/workspace-inspector/WorkspaceWorkbench.tsx)
  отправляет явное сохранение с `expected_content`; после успеха обновляет
  запросы файла, дерева и review. UI показывает конфликт и даёт Reload/Discard.
- [Node](../../../../crates/uprava-node/src/runtime/workspace.rs) проверяет
  границу workspace, тип и размер файла, symlink и ожидаемое содержимое.
  Сохранение проходит через Core и Node, сохраняя границу полномочий.
- Monaco загружается лениво, языковые модули подключаются по необходимости.
  Дерево загружает каталоги по раскрытию и явно показывает усечение/ошибку.

Проверки [черновиков](../../../../apps/web/src/features/workspace-inspector/WorkspaceDrafts.test.ts)
покрывают переход A→B→A, изоляцию placements и конфликт. Это свидетельство
задуманной семантики, а не результат нового запуска тестов или замер скорости.

## Где реализация требует проверки

Статическое чтение кода выявило следующие механизмы и связанные гипотезы:

| Подтверждённый механизм | Что проверить перед изменением |
| --- | --- |
| В [MonacoViews](../../../../apps/web/src/features/workspace-inspector/MonacoViews.tsx) при смене пути/placement уничтожаются editor и model; Source→Review размонтирует редактор | Стоимость повторного создания; сохранение undo, выделения, scroll и фокуса при возвращении |
| Каждый `onDidChangeContent` читает полный `model.getValue()` и обновляет общий React context черновиков | Время ввода на больших файлах, число render/commit и стоимость копирования строк/состояния |
| Diff editor пересоздаётся при изменении `original` или `modified` | Стабильность фокуса и положения при обновлении review |
| Файл и каталог запрашиваются через Core; чтение Core dispatch-ит команду Node | Долю сетевых, очередных, дисковых и клиентских задержек при открытии |
| [QueryClient](../../../../apps/web/src/app/providers.tsx) задаёт `staleTime: 2000`, отключает refetch при фокусе окна; Workbench предоставляет Refresh | Свежесть после изменения файла агентом и поведение повторного открытия |
| Дерево отображает элементы через `tree.getItems().map(...)` | Рост работы браузера при многих раскрытых каталогах |

Из этих механизмов нельзя вывести фактическую задержку. Например, локальный
ввод уже не ждёт ответа Node; перенос сохранения в другой транспорт сам по
себе не исправит стоимость обработки клавиатуры. React-state черновиков
сохраняет текст, но не равнозначен сохранению Monaco model или undo history.

## Решение для следующей итерации

Сохранить возможность ручного вмешательства, а объём редактора выбрать после
профиля. Сравнить три узких варианта: довести существующее встраивание;
ввести долговечные локальные буферы с отдельной синхронизацией; предоставить
переход во внешний редактор с адресуемым workspace. Более тяжёлая IDE имеет
цену запуска, интеграции, безопасности и сопровождения; её нельзя выбрать
только по ширине возможностей.

Приёмка должна пройти один повторяемый сценарий: открыть файл → изменить →
переключиться → вернуться → увидеть изменение агента → разрешить конфликт →
сохранить → проверить diff. Отдельно проверяются разрыв сети, ошибка сохранения
и закрытие страницы. Для ввода, открытия, переключения и сохранения нужны
раздельные измерения и заранее объявленный бюджет задержек, а также оценка
владельца после нескольких обычных рабочих сеансов. Протокол исследования —
в [редакторе и отзывчивости](../research/05-editor-and-responsiveness.md).
